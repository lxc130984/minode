## 3. 健康度复查机制

AI 协作项目的风险不是「写不出来」，而是**悄悄偏离**：文档与实现分家、旧路径与新路径并存、
不变量没有被测试钉住。所以复查分两档，**触发即做，不靠自觉**。

### 3.1 轻量复查（每个里程碑完成后）

1. 三件套：`vp check` → `vp run type-check` → `vp test`；
2. 浏览器冒烟：加载 → 重置 → 本轮改动的主路径（真实输入，非合成事件）；
3. 台账与索引：08 篇追加本里程碑的决策；docs/README 与根 README 的进度行更新；
4. 把本轮「摸清的坑」写进对应文档的坑清单（06 §9 这种）。

### 3.2 深度复查（满足任一条件即触发）

| 触发条件         | 阈值                                        |
| ---------------- | ------------------------------------------- |
| 完成里程碑数     | 每 3 个（**M9 完成后 = 第一次**）           |
| 测试总数         | +25（当前 65 → 90）                         |
| `engine/` 文件数 | +3（当前 9 → 12）                           |
| 同类 bug 复发    | 例如再次出现 DOM/模型漂移、重复引用、漏刷新 |
| 距上次深度复查   | > 14 天                                     |

### 3.3 深度复查清单（7 项，逐项给结论）

1. **文档↔实现一致性**：07 篇的 API 逐个在源码里找；06 篇的 CSS 值/色板与 `main.css` 对照；
   01/02 篇的语义与 `computeRet`/`evalNode` 对照。**stale 一律当场改**。
2. **死代码与并存旧路径**：`grep` 未使用的导出/助手；确认没有「两套做法」同时活着（历史上的
   `findRecipeFor`、`absorbDrop`、`hoverRoleOf` 都是这么清掉的）。
3. **不变量与回归覆盖**：摘挂不变量（节点只在一处）、增量归一化（祖先链刷新）、
   落位自愈、undo 去重与裁剪、存档 round-trip——每条都要有具名测试。
4. **性能基线**：400 节点点击到下一帧 ≈ 1 帧（02 篇 §8）；拖拽期间 `.tree` 高度不变；
   结构变更的归一化只走「受影响 + 祖先链」。
5. **依赖与工具链**：`vp env doctor`；`vp why <pkg>` 确认没有多余依赖；三件套在干净 `vp install` 后仍绿。
6. **存档兼容**：`SAVE_VERSION` 与迁移表（v1→v2 已实现）；未知 `type` 仍隔离为 `?` 且可收起/删除；旧字段被安全忽略。
7. **复杂度预算**：engine 行数/文件数、store 动作数、组件数对照 05 篇的预算；超了就说明来由。
