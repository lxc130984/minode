# 09 · 路线图与健康度复查

本篇回答两个问题：**接下来做什么**、**什么时候停下来检查项目健康度**。
决策理由见 08 篇（ADR 台账）。

## 1. 已落地

- **引擎**：应用树求值器（`()` = eval、手持隐式实参、签名哈希派发、增量归一化）、
  物品库存纯函数（容量/原子扣费/分解 30% 返还）、存档 v4（v1→v4 链式迁移）、撤销树。
- **生产线交互**：节点选择面板、放置模式（虚影 + FLIP 落点挤压 + 连续建造 +
  边缘自动滚动）、回收分解、箱子（物品容器）、背包手持。
- **Lisp 式渲染**：完全纵向大纲（emacs 风格）、括号（拖把手 + 折叠开关 + 配对高亮）、
  极浅缩进标线、幽灵实参槽、入场动画（「括号生长」）。
- **内容**：六层加工链 + 矿井 + 森林/斧头（手持演示）+ 箱子。
- **工程**：89 个单测、三件套全绿、GitHub Pages 自动部署（D-33）、
  store 分层（display/feedback/content-demo，D-32）、docs 00-10 全面重写（D-33）。

## 2. 接下来（按顺序，一次一个）

| 里程碑 | 内容                                                                       | 验收                                                                          |
| ------ | -------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| M9     | **内容扩张**：多工具配方（斧/锯/镐各开一条手持链）、资源消耗出口、配方加深 | 新增一条 ≥4 层链有单测；每把工具有一条手持配方用例（forest(axe)→wood 是范式） |
| M10    | **连续生产（自动化）**：不靠点击的周期性产出机制                           | 必须先出设计（不得破坏静态 `ret`，D-02 后果）；再做实现与可关停开关           |

必须单独设计评审；M11 在内容稳定后才有意义。

## 3. 健康度复查机制

AI 协作项目的风险不是「写不出来」，而是**悄悄偏离**：文档与实现分家、旧路径与新路径
并存、不变量没有被测试钉住。复查分两档，**触发即做，不靠自觉**。

### 3.1 轻量复查（每个里程碑完成后）

1. 三件套：`vp check` → `vp run type-check` → `vp test`；
2. 浏览器冒烟：重置 → 本轮改动的主路径（建造 → eval → 回收 → 读档）；
3. 台账与索引：08 篇追加决策；docs/README 与根 README 的进度行更新；
4. 把本轮「摸清的坑」写进对应文档的坑清单（06 §9 这种）。

### 3.2 深度复查（满足任一条件即触发）

| 触发条件         | 阈值                                    |
| ---------------- | --------------------------------------- |
| 完成里程碑数     | 每 3 个（**M9 完成后 = 第一次**）       |
| 测试总数         | +25（当前 89 → 114）                    |
| `engine/` 文件数 | +3（当前 10 → 13）                      |
| 同类 bug 复发    | 再次出现 DOM/模型漂移、重复引用、漏刷新 |
| 距上次深度复查   | > 14 天                                 |

### 3.3 深度复查清单（逐项给结论）

1. **文档↔实现一致性**：07 篇 API 逐个在源码里找；06 篇 CSS 值与 `main.css` 对照；
   01/02 篇语义与 `computeRet`/`evalNode` 对照。**stale 一律当场改**。
2. **死代码与并存旧路径**：grep 未使用的导出/助手；确认没有「两套做法」同时活着。
3. **不变量与回归覆盖**：摘挂不变量、增量归一化、落点自愈、undo 去重与裁剪、
   存档 round-trip——每条都要有具名测试。
4. **性能基线**：400 节点点击到下一帧 ≈ 1 帧；反馈状态保持按节点分键。
5. **依赖与工具链**：`vp env doctor`；`vp why <pkg>` 无多余依赖；干净 install 后三件套仍绿。
6. **存档兼容**：v1/v2/v3 迁移 round-trip；未知 `type` 隔离为 `?` 且可回收。
7. **复杂度预算**：engine 行数/文件数、store 动作数对照 05 篇 §10；超了说明来由。
