# 00 · 总览：节点树即程序

> 本系列文档是 minode-beta 的实现规范。读完应能从零复现出等价的骨架。
> 文档只描述**机制与架构**；玩法数值与具体配方全部属于内容包（见 03 篇）。

## 一句话

玩家维护一棵**可拖拽重排的表达式树**：父节点是函数，子节点是它的实参；
**点击节点 = 对它做一次 eval**。结果（`[]`）是**静态**算好的；点击时只有**函数**（有配方的类型）会响应并产出一件对应物品进背包，**符号**（没有配方的类型）点击无响应。

```
发动机厂[发动机]
  装配台[机械零件]
    轧机[钢板]
      锻炉[钢]
        冶炼炉[铁]
          铁矿石  煤炭  氧气
        煤炭
      冶炼炉[铁]
        铁矿石  煤炭  氧气
    冶炼炉[铁]
      铁矿石  煤炭  氧气
  锻炉[钢]
    冶炼炉[铁]
      铁矿石  煤炭  氧气
    煤炭
```

「发动机厂」是函数：它的实参（装配台、锻炉）各给出自己的静态结果（机械零件、钢），
配方检测命中 → 点击它产出 1 台发动机进背包。点「铁矿石」这类符号则没有任何响应。
配方对不上的节点显示 `[?]`，点击也不产出。

## 与 Lisp 的对应关系

| Lisp                    | 本游戏                                           |
| ----------------------- | ------------------------------------------------ |
| 表达式 `(f a b c)`      | 节点 + 子节点列表（顺序 = 实参顺序）             |
| 函数位置                | 节点类型（`NodeDef`，注册表条目）                |
| 实参                    | 子节点                                           |
| `eval`                  | 点击时的求值：只有被点的函数执行（符号无响应）   |
| `apply`                 | 配方：签名匹配 `(节点类型 × 实参签名) → 产物`    |
| 求值结果                | 节点右边的 `[]`；父节点求值时作为实参值读取      |
| 未定义应用              | `[?]`（空手配方检测不通过，不产出）              |
| 手持物                  | 隐式实参（点击时排在实参最前参与检测，02 篇 §3） |
| reader / 文本语法       | **无**：树由拖拽编辑，不是文本解析               |
| 宏 / 闭包 / quote / set | **无**：刻意排除（见 05 篇「解释器决策」）       |

两条关键性质：

1. **求值是动作**：点击 = 「eval 光标处的 s 表达式」——只有**被点的那一个节点**求值，
   命中配方即产出物品进背包。手持物作为**隐式实参**参与检测（如手持斧头点森林 → 木材）。
2. **求值是局部的、不消耗的**：只触及被点节点（子节点只提供静态返回值）；
   节点是 symbol，eval 不消耗它。
3. **经济是生产线式的（D-26/D-27）**：资产只有物品（背包）；建造节点 = 在选择面板选类型 +
   放置模式（虚影）左键消耗物品；回收 = **分解成原材料、按返还率（默认 30%）折算**。

## 核心循环

```
点击节点（空手/工具） ──▶ 整棵子树求值：每个节点产出自己的结果物品
                              │
                        物品进背包 ──▶ 放置成新节点（方块）──▶ 构建更深/更宽的树
                              │
                        更深的树 = 一次点击产出更多种/更多的物品
                              │
                        更深/更宽的函数树 ──▶ 点击产出更多种类的物品
```

## 术语表

术语的**唯一事实源**是 [10 篇术语表](10-glossary.md)（新概念先入表再用；代码标识符与术语一一对应）。
最核心的几个：

| 术语              | 定义                                                                  |
| ----------------- | --------------------------------------------------------------------- |
| 节点 Node         | 表达式树的最小单元：类型 + 实参（子节点）+ 返回值（`[]`）             |
| 节点类型 NodeType | 注册表条目：**有配方 = 函数**（点击 eval）、**无配方 = 符号**（惰性） |
| 求值 eval         | Lisp 的 eval；点击 = eval 光标处的 s 表达式（只对被点节点做一次）     |
| 返回值 ret        | 节点 `[]` 里的静态值；`[?]` = 空手配方检测不通过                      |
| 手持 held         | 选中格的节点类型；作为隐式实参参与点击检测（02 篇 §3，D-25）          |
| 配方 recipe       | `(节点类型, 实参签名) → 产物` 的映射                                  |
| 产物 yield        | 配方输出的东西：节点类型或资源（上位词，仅配方语境）                  |
| 容器 container    | 有格位、存节点堆的界面统称：节点背包、箱子（04 篇）                   |

## 设计决策摘要

| #   | 决策                                                           | 理由                                                   | 详见  |
| --- | -------------------------------------------------------------- | ------------------------------------------------------ | ----- |
| 1   | 不写通用 Lisp 解释器；写「应用树求值器」                       | 树是数据不是文本；内容由 TS 注册表提供；性能与类型安全 | 05    |
| 2   | 结果静态算（结构变更时一次后序遍历）；**点击只 eval 被点节点** | 符号惰性、函数才响应；没有「内部 eval」                | 02    |
| 3   | 结果即 `[]`；配方检测不通过 → `[?]` 且不产出                   | 纯表达式语义：有值才有产出                             | 02    |
| 4   | 求值 = 配方数据 + 产出路由（无处理器派发）；效果原语只有 gain  | 删掉求值通道（D-25）：手持 = 隐式实参一条规则覆盖      | 02    |
| 5   | 没有节点级存储：节点只在树/容器，资源只在仓库                  | 节点保持表达式语义；经济闭环简单清楚                   | 04    |
| 6   | 容器交互 = 三动词（放置/收起/转移）+ 统一落位规则              | 一条心智模型 + 纯函数路由（D-24）                      | 04    |
| 7   | 单一 Pinia store 持有全部可变状态                              | 避免多 store 互相引用导致的数据流跳跃                  | 05    |
| 8   | 大数从第一天就用 Decimal（break_infinity.js）                  | 增量游戏必然溢出 float64；迁移成本远高于起始成本       | 05    |
| 9   | 注册表是可实例化对象，不是模块级单例                           | 测试隔离（alpha 需要 clear 注册表是教训）              | 03    |
| 10  | 存档为纯 JSON；未知内容 id 不摧毁存档（渲染为 `?`，可删除）    | 长期演进安全                                           | 03/05 |
