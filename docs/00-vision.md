# 00 · 总览：节点树即程序

> 本系列文档是 minode-beta 的实现规范，读完应能从零复现出等价的骨架。
> 文档只描述**机制与架构**；玩法数值与具体配方全部属于内容包（见 03 篇）。
> 术语的唯一事实源是 [10 篇术语表](10-glossary.md)。

## 一句话

玩家维护一棵**可拖拽重排的表达式树**，它是同构于 Lisp s 表达式的「活代码」：

- **节点就是 symbol，嵌套就是括号，`()` 表示 eval**；
- 点击一个**表达式**（渲染括号的节点）= eval 它自己的 `(…)`，产出物品进背包；
- 资产只有物品；**建造 = 消耗物品生成节点，回收 = 分解节点返还原材料**。

```
( 发动机厂[引擎]
   ( 装配台[零件]
      ( 轧机[板] …+10 )
      ( 冶炼炉[铁]
         铁矿石
         煤炭
         氧气 )
      … )
   ( 锻炉[钢] … ) )
```

「发动机厂」是函数：它的实参（装配台、锻炉）各给出自己的静态返回值（机械零件、钢），
配方检测命中 → 点击它产出 1 台发动机进背包。点「铁矿石」这类**裸符号**没有任何
效果（eval 属于括号，不属于单个节点，D-30）。

## 与 Lisp 的对应关系

| Lisp                    | 本游戏                                                       |
| ----------------------- | ------------------------------------------------------------ |
| 表达式 `(f a b c)`      | 节点 + 子节点列表（顺序 = 实参顺序）                         |
| 函数位置                | 节点类型（`NodeDef`，注册表条目）                            |
| 实参                    | 子节点                                                       |
| `eval`                  | **`()` 表示 eval**：点击表达式（有括号的节点）= eval 它自己  |
| `apply`                 | 配方：`(函数类型 × 实参签名) → 产物` 的哈希表命中            |
| 求值结果                | 节点右侧的 `[]`；父节点检测时作为实参值读取                  |
| 未定义应用              | `[?]`（空手配方检测不通过；手持某物可能命中）                |
| 隐式实参                | **手持物**：选中背包物品参与点击检测（如斧头 × 森林 → 木材） |
| reader / 文本语法       | **无**：树由拖拽与放置模式编辑，不是文本解析                 |
| 宏 / 闭包 / quote / set | **无**：刻意排除（见 05 篇「解释器决策」）                   |

三条关键性质：

1. **求值是动作也是局部**：只有被点的那个表达式产出一份产物；子节点只提供静态返回值，
   不被触发；祖先与兄弟不受影响。
2. **求值不消耗**：节点是 symbol，eval 不消耗它（避免「消耗增加复杂度」，
   真正的成本是建造节点）。
3. **经济是生产线式的**（Mindustry 式，非沙盒式）：资产只有物品（背包，容量受限）；
   建造 = 选择面板选类型 + 放置模式（虚影）左键消耗物品；回收 = 分解成原材料
   按返还率（默认 30%）折算。物品 ↔ 节点只在建造/回收处兑换。

## 核心循环

```
点击表达式（如 矿井[铁矿]）
   │  eval：配方检测（含手持隐式实参）
   ▼
物品进背包（容量受限）
   │  选择面板选类型 → 放置模式 → 左键建造
   ▼
新节点上树（扣成本、可连续建造）
   │  更深/更宽的表达式 = 更高阶的配方可搭
   ▼
点击更高级的表达式 → 更值钱的物品 → ……
   （随时：× 回收返还 30% 原材料 / 拖拽重排 / 折叠收纳）
```

## 术语速查（详见 10 篇）

| 术语        | 定义                                                                 |
| ----------- | -------------------------------------------------------------------- |
| 节点 Node   | 表达式最小单元：类型 + 实参 + 返回值；只存在于树上                   |
| 函数 / 符号 | 有配方 = 函数（`()` 可点击 eval）；无配方 = 符号（原子，点击无效果） |
| 括号        | 表达式边界 token；拖拽把手 + 折叠开关 + 配对高亮                     |
| 返回值 ret  | 节点 `[]` 里的静态值；`[?]` = 空手检测不通过                         |
| 物品 item   | 背包里可数的东西，建造的货币；与节点类型 id 可同名                   |
| 手持 held   | 选中的背包物品；作为隐式实参参与点击检测                             |
| 建造 / 回收 | 消耗 `cost` 放置节点 / 分解成原材料按 30% 返还                       |
| 产物 yield  | 配方输出（全部是物品，进背包）                                       |

## 设计决策摘要

| #   | 决策                                                             | 理由                                           | 详见  |
| --- | ---------------------------------------------------------------- | ---------------------------------------------- | ----- |
| 1   | 不写通用 Lisp 解释器；写「应用树求值器」                         | 树是数据不是文本；内容由 TS 注册表提供         | 05    |
| 2   | **`()` 表示 eval**：只有表达式可点击求值，裸符号实参无效果       | 点击与 eval 解耦；eval 属于括号                | 02    |
| 3   | 返回值静态算（结构变更时增量重算）；点击只是「再检测一次」       | 显示零副作用；点击只有产出                     | 01/02 |
| 4   | 手持 = 隐式实参（先含手持签名、再回落空手）                      | 一条规则覆盖「多样化点击」，删掉整套通道注册表 | 02    |
| 5   | 生产线模型：资产只有物品；建造消耗 / 回收分解返还                | 节点只是表达式，资产只在背包                   | 04    |
| 6   | Lisp 式渲染：完全纵向大纲 + 括号 + 悬挂缩进（emacs 风格）        | 括号显形嵌套、宽度有界、编辑器手感             | 06    |
| 7   | 单一 Pinia store 持有全部可变状态（分层：display/feedback 文件） | 避免多 store 数据流跳跃                        | 05    |
| 8   | 大数从第一天就用 Decimal；全仓唯一出口 `engine/num.ts`           | 增量游戏必然溢出 float64                       | 05    |
| 9   | 注册表是可实例化对象，不是模块级单例                             | 测试隔离（alpha 教训）                         | 03    |
| 10  | 存档纯 JSON、链式迁移（v1→v4）；未知内容 id 不摧毁存档           | 长期演进安全                                   | 01    |
