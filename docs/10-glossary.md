# 10 · 术语表（唯一词汇事实源）

本表是全项目（文档 / 代码 / UI 文案 / 提示语）的**唯一术语来源**。

使用规则：

1. 新文档、新代码、新 UI 文案只允许使用本表词条；要引入新概念，**先入表再用**；
2. 代码标识符与术语一一对应（§5 对照表），改名先改本表；
3. §6 的废弃词不得再出现在新代码与新文档（08 篇 ADR 的历史记述除外）；
4. 同名不同义、同义不同名的词一律合并或拆开——术语表里不允许「一词多义」。

---

## 1. 表达式层（游戏的本体）

整个游戏同构于 Lisp 的 s 表达式：**节点就是 symbol，嵌套就是括号嵌套**。

| 术语            | 代码标识符                    | 定义                                                                                                           |
| --------------- | ----------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 表达式          | `GameNode` 树                 | 一个节点 + 它的子节点构成的整体，同构于 `(f a b)`：父节点 = 函数，子节点 = 实参                                |
| 节点            | `GameNode`                    | 表达式的最小单元：类型 + 实参 + 返回值。节点就是 symbol                                                        |
| 节点类型        | `NodeTypeId` / `NodeDef`      | 注册表条目（Lisp 里的「名字」）。定义在内容包里，id 是存档契约                                                 |
| 函数（节点）    | `recipesFor(type).length > 0` | 有配方的类型：点击会求值（eval）并产出                                                                         |
| 符号（节点）    | 无配方                        | 没有配方的类型：返回值 = 自身（原子），点击无响应，只作实参                                                    |
| **求值 eval**   | `evalNode()`                  | 就是 Lisp 的那个 eval。点击 = 「**eval 光标处的 s 表达式**」：只求值被点的那一个节点，内层节点只提供静态返回值 |
| **返回值 ret**  | `RetState` / 节点右侧 `[]`    | 表达式静态求值的结果，显示为 `name[值]`——写给玩家看的，让玩家看懂这棵子树算出什么                              |
| 未命中          | `unresolved` / `[?]`          | **空手**配方检测不通过。注意：手持某物时可能命中（§4 手持），`[?]` 只承诺「空手点不出东西」                    |
| 配方            | `RecipeDef`                   | `(函数类型 × 实参签名) → 产物` 的映射，纯数据                                                                  |
| 签名            | `childrenSignatureKey()`      | 实参返回值构成的键：默认多重集（顺序无关、数量有关），可选 ordered（顺序敏感）                                 |
| **产物**        | `Yield` / 配方 `out`          | 配方输出的东西：节点类型或资源。这是「节点 ∪ 资源」的上位词，**只允许在配方语境使用**                          |
| 结算            | `applyOps()`                  | 引擎按产出路由落地效果（节点类型 → 容器；资源 → 仓库）                                                         |
| **eval 不消耗** | —                             | 设计决策：节点是 symbol，eval 不消耗它。同一棵树可以无限点击。消耗机制只会增加复杂度（用户拍板）               |

## 2. 资产层（玩家拥有什么）

**只有两种实体**（没有「物品」这个第三层）：

| 术语     | 代码标识符               | 定义                                                   |
| -------- | ------------------------ | ------------------------------------------------------ |
| 节点     | `GameNode` / `NodeStack` | 可放置的实体。在树上 = 完整表达式；在容器里 = 类型堆   |
| 资源     | `ResourceDef`            | 不可放置的纯数量（铁 / 钢 / 木材……），只存在于资源仓库 |
| 资源仓库 | `resources`              | `id → 数量` 的只读列表，无槽位、不参与拖拽             |
| 产出路由 | `gain(id, count)`        | 产物 id 是节点类型 → 进容器；否则 → 仓库累加           |
| 资源消耗 | —                        | **预留**：未来配方可能消耗仓库库存（当前只进不出）     |

## 3. 容器层（东西放在哪）

| 术语                     | 代码标识符        | 定义                                                                           |
| ------------------------ | ----------------- | ------------------------------------------------------------------------------ |
| 容器                     | —                 | 有格位、存放节点堆的界面统称：节点背包、箱子。只讨论「容器之间转移」时用这个词 |
| 节点背包                 | `nodeBag`         | 常驻侧栏的容器（27 格），手持的来源                                            |
| 箱子                     | `chestContents`   | 带内容的特殊节点（`NodeDef.panel = 'storage'`），点击打开浮动窗口              |
| 格 / 槽位                | `SlotRef.index`   | 容器里的一个位置，扁平下标                                                     |
| 堆                       | `NodeStack`       | 格的内容：`类型 × 数量`（单堆上限 64）                                         |
| 并堆                     | `bagRearrange` 等 | 同类两堆合并到上限，溢出留在源格                                               |
| 节点背包里的节点没有身份 | `NodeStack.type`  | 容器里只有「类型 × 数量」；放置 = 消耗 1 个、**新建**节点（不是移动同一实例）  |

## 4. 交互层（玩家怎么操作）

生产线的核心循环：**选择面板选类型 → 放置模式（虚影）→ 左键建造 → 回收返还**。

| 术语         | 代码标识符                    | 定义                                                                                                       |
| ------------ | ----------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 选择面板     | `NodePalette.vue` / `palette` | 侧栏节点类型列表（名字 + 成本）；点击 = 进入/退出放置模式；付不起的暗淡                                    |
| **放置模式** | `placing`                     | 光标挂着**虚影节点**的持续建造状态：左键 = 按落点建造（不 eval）；右键 / Esc / 再点同款 = 取消；可连续建造 |
| 虚影节点     | `PlacementGhost.vue`          | 跟随指针的建造预览（松手不消失）；树上同步显示**落点挤压**（`place-gap-*` 让位 + 指示线）                  |
| 建造         | `place(type, owner, index)`   | 消耗 `cost` 在落点插入新节点（`payCost` 原子扣费；资源不足提示缺口）                                       |
| 回收         | `recycle(nodeId)`             | `×` 或拖到侧栏：移除节点（子节点上移），**全额返还成本**（+箱子内容）                                      |
| **手持**     | `heldItem`（= 选中背包物品）  | 单击背包行选中（再点取消）。作为**隐式实参**参与点击检测（见下）                                           |
| 折叠         | `toggleFold()` / `folded`     | `[-]` 按钮：纯视觉收合子列表（**≠ 回收！**）                                                               |
| 浮动窗口     | `panel`                       | 箱子等点开的窗口（`NodeDef.panel` 是节点「可开窗」的能力字段；开窗会取消放置模式）                         |
| 树 / 主区    | `roots` / `.tree`             | 主界面的表达式树编辑区。**不再叫「放置界面」**                                                             |

### 手持 = 隐式实参（唯一的「多样化点击」机制）

手持物参与**被点击节点**的配方检测，如同一个放在实参列表最前面的隐式实参：

```
手持斧头，点击 森林[]
  → 先按「斧头 + 子实参」签名检测 → 命配 forest(axe) → 产出 木材
手持镐，点击 矿井[铁矿]
  → 「镐 + 铁矿」签名无命中 → 回落空手签名 → 命中 mine(iron_ore) → 产出 铁矿石
```

- 检测顺序固定：**先试含手持的签名，再回落空手签名**——手持永远不会「打断」已有配方；
- 内层求值永远是经典 eval：手持只作用于被点的那一层，静态返回值（`[]` 显示）不受手持影响；
- 旧的「求值通道」（`node:x` / `class:x` / 两轴处理器注册表）已删除，见 08 篇 D-25。

## 5. 代码命名对照（术语 ↔ 标识符）

| 术语     | 标识符                                                   | 说明                                                                                     |
| -------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 节点     | `GameNode` / `createNode`                                |                                                                                          |
| 返回值   | `RetState` / `computeRet` / `normalizeTree`              | `ret` 字段                                                                               |
| 产物     | `Yield { id, count }`                                    | 曾用名 `ItemAmount`（已废弃）                                                            |
| 签名     | `childrenSignatureKey(children, mode, held?)`            | 第三个参数 = 手持隐式实参                                                                |
| 收起     | `stow(nodeId)`                                           | 曾用名 `collapseToBag`                                                                   |
| 折叠     | `toggleFold(id)` / `node.folded`                         | 曾用名 `toggleCollapse` / `collapsed`（存档字段仍叫 `collapsed`，属线上格式）            |
| 放置     | `placeOne(from, owner, index)`                           | 合并了旧 `placeFromBag` / `placeOneFromBag` / `placeOneFromBagAt` / `materializeFromBag` |
| 转移     | `transferOne(ref)` / `execDrop(action)`                  | `execDrop` 执行 `routeDrop` 的路由结果                                                   |
| 落位路由 | `routeDrop(from, to, stackAt)`                           | 纯函数，`utils/drop-action.ts`                                                           |
| 落点读取 | `slotUnderPointer` / `treeZoneUnderPointer` / `readDrop` | DOM 层，`utils/tree-drop.ts`                                                             |
| 箱子内容 | `chestContents`                                          | 曾用名 `containers`                                                                      |
| 手持     | `heldItem`（computed：选中格类型）                       |                                                                                          |
