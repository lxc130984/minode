# 01 · 节点模型与显示规范

本篇定义节点的数据结构、chip 显示形态、返回值语义、归一化管线与序列化形状（v4）。
求值算法见 02 篇；注册表定义见 03 篇。

## 1. 显示规范（chip 文本与括号）

节点的标准形态是一行纯文本，表达式外包**括号 token**（D-29/D-30）：

```
( 冶炼炉[铁]
   铁矿石
   煤炭
   氧气 )
```

完整语法：

```
node   := '(' chip 实参列表 ')'    —— 表达式（有实参 / 函数 / 根层落单）
        | chip                      —— 裸符号实参（无括号）
chip   := name ret?
name   := NodeDef.name             —— 未注册类型显示 '?'
ret    := 省略 | '[' 值 ']' | '[?]'
值     := registry.shortOf(id)，多值空格分隔、数量 > 1 写 短名×N
行尾   := '×'（回收按钮）
```

### 1.1 括号规则（D-30）

| 节点形态       | 括号渲染                                                        |
| -------------- | --------------------------------------------------------------- |
| 有实参（展开） | `( 头部` 在行首 + 实参逐行 + 子树末尾独立一行 `)`               |
| 有实参（折叠） | `( 头部[ret] …+N )`（括号形态完整保留）                         |
| 函数、无实参   | `( 头部[?] )`（空应用）                                         |
| 根层落单节点   | 也包 `()`——`()` 表示 eval，落单节点也可点击（求值结果自然为无） |
| 符号（无配方） | **无括号**（原子；作实参时裸露）                                |

括号同时是：**拖拽把手**（拖 = 移动整棵子表达式，D-29）、**折叠开关**
（点 `(`/`)` 折叠展开、点 `…+N` 徽标展开，D-30/D-31）、**配对高亮**触发点
（悬停任一端 → 两端同时亮，emacs show-paren，D-31）。

### 1.2 `[ret]` 的显示条件

| 结果状态             | 条件                                             | 显示         |
| -------------------- | ------------------------------------------------ | ------------ |
| `none`（无结果概念） | 类型未注册                                       | 省略         |
| `unresolved`         | 类型有配方，但实参签名未命中；或任一子节点未识别 | `[?]`        |
| `value`              | 配方检测命中 / 原子自返                          | `[短名]`     |
| `value` 且原子自返   | 结果 = 本节点类型本身（符号）                    | 省略（见下） |

**手持可命中（D-34）**：`unresolved` 且手持物可命中时，`retOf` 显示**预测产物**并挂
`.is-held-hint`（虚线下划线，与悬停下划线同语言）——`森林[?]` 手持斧头时显示为
`森林[木]`（虚线），点击必得木材；放下回到 `[?]`。

**原子自返省略规则**（`retDisplay: 'auto'`，默认）：值为单个条目、数量 1、且条目 id
等于本节点 `type` 时省略方括号——`铁矿石` 比 `铁矿石[铁矿石]` 干净。
内容作者可用 `retDisplay: 'always' | 'never'` 覆盖。

### 1.3 状态示例

| 情形                   | 文本                  |
| ---------------------- | --------------------- |
| 冶金配方检测通过       | `冶炼炉[铁]`          |
| 冶炼炉实参不符         | `冶炼炉[?]`           |
| 铁矿石（原子）         | `铁矿石`（无括号）    |
| 折叠（子树 12 个节点） | `( 轧机[板] …+12 ) ×` |
| 未注册类型（存档隔离） | `? ×`                 |

布局（完全纵向大纲、悬挂缩进 21px/层、极浅缩进标线）见 06 篇 §4。

## 2. 数据模型

```ts
// engine/types.ts
export interface GameNode {
  id: NodeId // 运行时唯一；不入存档（加载时重建）
  type: NodeTypeId // 注册表键
  children: GameNode[] // 实参列表；顺序 = 显示顺序 = 签名（ordered）顺序
  folded: boolean // 折叠（纯视觉，≠ 回收）；存档字段沿用线上名 collapsed
  ret: RetState // 返回值；由归一化重算，任何其他地方不得手改
}

export type RetState =
  | { kind: 'none' } // 未注册类型
  | { kind: 'unresolved' } // [?]
  | { kind: 'value'; items: readonly Yield[] }

export interface Yield {
  id: string // 物品 id（产物全部是物品）
  count: Decimal
}
```

三条纪律：

1. **`ret` 是派生缓存不是事实源**。事实源 = `children` + 注册表（配方定义）；
   任何读 `ret` 的逻辑都发生在归一化之后。
2. **节点没有存储**。玩家资产只有背包/箱子里的物品；节点只存在于树上。
   任何「节点内部囤东西」的机制都不属于本项目。
3. **节点 id 不入存档**：加载时整体重建，避免导入冲突（alpha 遗留问题）。

## 3. 注册表侧定义（节点相关字段）

字段全集见 03 篇；与节点形态直接相关的：

```ts
export interface NodeDef {
  id: NodeTypeId
  name: string // chip 主文本
  short?: string // `[]` 与提示用的紧凑名；默认 = name
  retDisplay?: 'auto' | 'always' | 'never' // 默认 auto
  toolClass?: string // 仅 UI 分类着色（k-tool）；不参与求值
  panel?: string // 点击打开的浮动窗口 id（'storage' = 箱子）
  cost?: readonly CostArg[] // 建造成本（物品）；回收时分解返还
}
```

约定：**物品与节点类型 id 允许同名**（`iron_ore` 既是物品又是可放置的符号节点，
一体两面）；注册表按两套命名空间分别校验唯一（见 03 篇 §6）。

## 4. 返回值（computeRet）

`computeRet(node, registry)` 是纯函数，规则按优先级：

1. 类型未注册 → `none`。
2. 类型有配方：任一子节点 `ret` 非 `value` → **传染** `unresolved`（不做部分匹配）。
3. 用「子节点返回值签名」做配方检测（02 篇 §4）：命中 → `value`（配方产物，
   全部是物品 id）；未命中 → `unresolved`。
4. 类型没有配方（符号）→ `value`（结果 = 自身，原子，显示时省略方括号）。

注意：静态返回值**不含手持**——手持只作用于被点击表达式的检测（02 篇 §3）。

## 5. 值流：结果如何向上传递

- 父节点的配方检测读**子节点的返回值**，所以「树的形状」= 配方的实参列表；
- 检测是**静态**的：只看子节点已算好的值，**不 eval 子节点**；
- 返回值沿树传染：任一子节点 `[?]` → 父节点也 `[?]`（配方断裂）；
- 树越深/越宽，可搭的配方越高阶——构筑本身就是成长。

## 6. 归一化（normalizeTree / 增量刷新）

结构变更（拖拽落定、建造、回收、读档）后调用：

```ts
export function normalizeTree(roots, registry): void // 全量：单次后序遍历，O(N)，幂等
store.afterStructureChange(affected?) // 增量：只重算「受影响节点 + 祖先链」
```

- **后序**（先子后父）：父节点直接用子节点已算好的 `ret` 拼签名；
- 增量刷新的种子必须**深者优先**（父要读到子的新值；历史上踩过，有注释钉住）；
- 不重排 `children`、不动 `folded`（折叠是 UI 状态，不影响数据）。

防环三层：拖拽 on-move 守卫（DOM 包含判断）→ `moveTreeNode` 的 `subtreeContains`
校验 → `writeList` 的子树包含校验。

## 7. 结构编辑规则

| 操作         | 语义                                                                          |
| ------------ | ----------------------------------------------------------------------------- |
| 拖拽         | 编辑实参结构：移动/重排节点；把手 = chip 或开/闭括号（拖括号 = 整棵子表达式） |
| 折叠         | 不渲染子列表（`v-if` 级卸载）→ 折叠态结构上无法拖入；默认只展 2 层            |
| 建造（放置） | 消耗 `cost` 在落点插入新节点（04 篇 §2）                                      |
| 回收 `×`     | 移除节点（子节点保持顺序上移），成本分解成原材料按返还率折算（04 篇 §3）      |

## 8. 序列化（存档形状 v4）

```ts
// engine/save.ts
export const SAVE_VERSION = 4

export interface SaveV4 {
  v: 4
  savedAt: number // 墙钟毫秒
  roots: SaveNode[]
  bag: Record<string, string> // 物品 → Decimal 文本
}

export interface SaveNode {
  type: NodeTypeId
  collapsed: boolean // 折叠态（线上字段名，运行时叫 folded）
  children: SaveNode[]
  chest?: Record<string, string> // 箱子内容（物品表）；非容器节点省略
}
```

规则：

- Decimal 一律 `toString()` 序化、`D(str)` 反序列化；
- 节点 id 不存（加载重建）；`ret` 不存（加载后 `normalizeTree` 重算）；
- 手持 / 放置模式是瞬态，不入存档；
- **迁移链 v1→v2→v3→v4**（04 篇 §6）：v3 的节点堆按**建造成本折算**成物品；
- **未知内容 id 不丢数据**：`type` 原样保留，注册表查不到按 `unknown` 处理
  （名称 `?`、无行为、可删除）。
