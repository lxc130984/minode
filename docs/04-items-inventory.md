# 04 · 背包与建造（生产线模型）

**资产只有一种：物品（item）。** 节点只存在于树上（它们是表达式，不是库存）。
两者只在两处兑换（docs/08 D-26）：

```
物品 --建造（选择面板 + 放置模式，原子扣 cost）--> 节点
节点 --回收（× 或拖到侧栏，分解成原材料 × 返还率）--> 物品
```

| 实体     | 是什么                 | 在哪                             |
| -------- | ---------------------- | -------------------------------- |
| **物品** | `ItemDef`（id + 名字） | **背包**（`物品 → 数量`）、箱子  |
| **节点** | `GameNode`（表达式）   | 只在树上；由建造产生、由回收销毁 |

---

## 1. 背包（bag）

```ts
type ItemStore = Readonly<Record<ItemId, Decimal>> // 无槽位：物品 → 数量

// engine/bag.ts（纯函数层）
bagTotal(store): Decimal                          // 总量（容量口径）
bagAdd(store, item, count, capacity): { store, rest }  // 容量内放入，rest = 装不下的
bagTake(store, item, count): { store, taken }
costEntries / canAfford / costGap / payCost       // 成本归一化/校验/原子扣费
decomposeCost / recycleRefund                     // 分解成原材料 × 返还率向下取整
```

- 容量按**总数量**计：`config.bagCapacity`（256）。超出部分丢弃并提示。
- **手持**：单击背包行 = 选中该物品为手持（作为隐式实参参与点击检测，02 篇 §3）；
  再点同款取消。开箱时背包行点击改为转移（§4）。

## 2. 建造：选择面板 + 放置模式（虚影）

**选择面板**（侧栏 `NodePalette.vue`）：按内容顺序列出全部节点类型——名字 + 建造成本
（`NodeDef.cost`，如 `铁矿×4 煤×2`）。付不起的类型名暗淡。单击 = 进入/退出放置模式。

**放置模式**（`placing: NodeTypeId | null`，Mindustry 式）：

1. **虚影跟随指针**（`PlacementGhost.vue`）：光标上一个普通样式的 chip + 树上落点处
   一个 `.place-ghost`（透明度 0.35，同 `sortable-ghost`）**真实插入目标列表**，
   兄弟节点自然挤开，带 **120ms FLIP** 补间（与容器 `:animation="120"` 同款手感）；
2. **左键 = 建造**：按指针落点（哪个列表的哪一位，`treeZoneAt` 二维中点判定）原子扣
   `cost`（`payCost`）、插入新节点、**保持放置模式**可连续建造；资源不足 → 提示缺口，
   不建造、不退出；
3. **取消**：右键（全局）/ `Esc` / 再点同款按钮；打开箱子窗口会取消放置模式；
4. 放置模式中树区左键**不触发 eval**（02 篇 §1）；**边缘自动滚动**：指针停在视口上下
   边缘 60px 内，rAF 循环滚页面并每帧重算落点；
5. 建造成功的表达式播放一次 `node-appear` 入场动画（180ms 淡入 + 闭括号行 240ms
   滑入——「括号合上」，D-31）。

## 3. 回收（×）＝分解成原材料

- 节点右侧 `×` 或**拖到侧栏**：节点移除（子节点上移）；
- 建造成本**分解成原材料**（`decomposeCost`：沿「唯一产物是该物品」的配方实参递归
  下钻，`ItemDef.raw` 的原材料与无配方物品为止，带环保护），再按 `config.recycleRate`
  （默认 0.3）**向下取整**返还——例：冶炼炉（铁矿×4 煤×2）→ 铁矿×1；
  箱子（铁×4）→ 铁分解为 铁矿×1 煤×1 氧×1；
- 箱子节点被回收：内容是玩家存货，**原样**返还背包；
- 背包装不下的部分丢弃并提示。

## 4. 箱子（带内容的特殊节点）

```ts
chestContents: Record<NodeId, ItemStore> // 运行时按节点 id 索引；存档挂在节点条目上
```

- 点击箱子节点 = 打开浮动窗口（标题栏可拖动；树蒙灰锁定，点灰层关闭）；
- 箱子 = 与背包同款的物品表，容量 `config.chestCapacity`（128）；
- **转移手势**（背包行 / 箱子行，无拖拽无槽位）：
  - 背包行：开箱时**单击 = 转 1 个**进箱子、**双击 = 整项**转入；未开箱时单击 = 选手持；
  - 箱子行：**单击/滚轮 = 取 1 个**回背包、**双击 = 整项**取回；
  - 容量不够就转能装下的部分。

## 5. 拖拽（只剩树内移动）与滚动

- 树是**完全纵向大纲**（宽度有界）：纵向随页面滚动；
- **树内移动**（重排表达式 = 编辑实参顺序/层级）：把手 = chip **或开/闭括号**
  （拖括号 = 移动整棵子表达式，D-29）；落点以 SortableJS plan 为准（真实浏览器里
  可靠），plan 退回源列表（跨列表 drop 被取消的征兆）时才用指针兜底（D-29 教训）；
  走 `writeList`（先摘后插，节点永不重复引用，D-05）；
- 大子树落到第 3 层及以下自动折叠（保持视图紧凑，D-28）；
- **拖到侧栏 = 回收**（`pointerOverSidebar` 指针判定）；
- 背包/箱子不参与拖拽（物品表无槽位）；放置模式的落点不用拖拽（虚影 + 左键）；
- 拖拽悬停空实参列表 → **幽灵实参槽**（虚线框 76×18，绝对定位不回流，D-31）。

## 6. 存档（`SAVE_VERSION = 4`）

```jsonc
{ "v": 4, "savedAt": 0, "roots": [...], "bag": { "iron_ore": "12", "iron": "3" } }
// 带内容的节点把物品表挂在节点条目上：
// { "type": "chest", "collapsed": false, "children": [], "chest": { "coal": "7" } }
```

- 节点 id 不入档；`bag` 数量用字符串存（Decimal 纪律）；手持/放置模式是瞬态，不入档；
- **迁移**（`engine/save.ts`）：**v3 → v4**——v3 的节点背包堆与旧 `resources` 合并成
  v4 `bag`：同名物品直接折算；节点类型按其**建造成本 × 数量**折算；未知 id 丢弃；
  更早的 v1/v2 时代格式已移除（D-36），读到未知版本抛错、调用方保持现状。

## 7. 不变量（`store.spec` 有具名用例）

1. 同一节点在树中只出现一次（`writeList` 先摘后插）；
2. 建造是**原子**的：`payCost` 失败不动背包、不插节点；
3. 回收 = 成本分解 × 返还率（向下取整）+ 箱子内容原样（溢出才丢弃并提示）；
4. 转移前后「背包 + 箱子」总数不变（容量截断除外，且有提示）；
5. 结构变更后只重算「受影响节点 + 祖先链」的 `ret`（D-06）。
