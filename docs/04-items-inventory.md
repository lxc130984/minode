# 04 · 背包、选择面板与建造（生产线模型）

**资产只有一种：物品（item）。** 节点只存在于树上（它们是表达式，不是库存）。
两者只在两处兑换（docs/08 D-26）：

```
物品 --建造（选择面板 + 放置模式，消耗 cost）--> 节点
节点 --回收（× 或拖到侧栏，全额返还 cost）--> 物品
```

| 实体     | 是什么                 | 在哪                             |
| -------- | ---------------------- | -------------------------------- |
| **物品** | `ItemDef`（id + 名字） | **背包**（`物品 → 数量`）、箱子  |
| **节点** | `GameNode`（表达式）   | 只在树上；由建造产生、由回收销毁 |

---

## 1. 背包（bag）

```ts
type ItemStore = Readonly<Record<ItemId, Decimal>> // 无槽位：物品 → 数量

// engine/bag.ts（纯函数层）
bagTotal(store): Decimal                          // 总量（容量口径）
bagAdd(store, item, count, capacity): { store, rest }  // 容量内放入，rest = 装不下的
bagTake(store, item, count): { store, taken }
costEntries / canAfford / costGap / payCost       // 建造成本的归一化/校验/原子扣费
```

- 容量按**总数量**计：`config.bagCapacity`（256）。超出部分丢弃并提示（`gain` 的 `rest`）。
- 物品与节点类型 id **允许同名**：`iron_ore` 既是背包里的物品，也是可放置的实参节点。
- **手持**：单击背包行 = 选中该物品为手持（作为隐式实参参与点击检测，02 篇 §3）；
  再点同款取消。开箱时背包行点击改为转移（§4）。

## 2. 建造：选择面板 + 放置模式（虚影）

**选择面板**（侧栏 `NodePalette.vue`）：按内容顺序列出全部节点类型——名字 + 建造成本
（`NodeDef.cost`，如 `铁矿×4 煤×2`）。付不起的类型名暗淡。单击 = 进入/退出放置模式。

**放置模式**（`placing: NodeTypeId | null`，= 「无须按住的 vue-draggable 拖拽」）：

1. **光标跟随一个普通样式的 chip**（相当于拖拽影像，`place-cursor`）；
2. **落点预览完全复刻 SortableJS 的插入预览**：一个半透明 ghost（`.place-ghost`，
   透明度同 `sortable-ghost`）**真实插入目标列表的落点位**，兄弟节点自然挤开；
   空列表在 `.app.is-placing` 下展开为落点条；
3. **左键 = 建造**：按指针落点（哪个列表的哪一位）扣 `cost`、插入新节点（ghost 是外来
   DOM，真实拖拽开始时立即摘除，避免污染 SortableJS 的列表项映射）；
   **保持放置模式**，可连续建造。放置模式中左键**不触发 eval**；
   资源不足 → 提示缺口（`资源不足：还差 铁矿×2`），不建造、不退出；
4. **取消**：右键（全局）/ `Esc` / 再点同款按钮；
5. 打开箱子窗口会取消放置模式（树被锁定）。

建造动作：`place(type, owner, index)`（模型层，可单测）与 `placeAt(x, y)`（指针包装）。
落点读取用 `treeZoneAt`（`elementFromPoint` → `.root-list` / `.kids` → 插入位）。

## 3. 回收（×）＝分解成原材料

- 节点右侧 `×` 或**拖到侧栏**：节点移除（子节点上移）；
- 建造成本**分解成原材料**（`decomposeCost`：沿「唯一产物是该物品」的配方实参递归下钻，
  `ItemDef.raw` 的原材料与无配方物品为止，带环保护），再按 `config.recycleRate`
  （默认 0.3）**向下取整**返还——例：冶炼炉（铁矿×4 煤×2）→ 铁矿×1；
  箱子（铁×4）→ 铁分解为 铁矿×1 煤×1 氧×1；
- 箱子节点被回收：内容是玩家存货，**原样**返还背包；
- 背包装不下的部分丢弃并提示。

## 4. 箱子（带内容的特殊节点）

```ts
chestContents: Record<NodeId, ItemStore> // 运行时按节点 id 索引；存档挂在节点条目上
```

- 点击箱子节点 = 打开浮动窗口（标题栏可拖动；树蒙灰锁定，点灰层关闭）；
- 箱子 = 与背包同款的物品表，容量 `config.chestCapacity`（128）；
- **转移手势**（背包行 / 箱子行，无拖拽无槽位）：
  - 背包行：开箱时**单击 = 转 1 个**进箱子、**双击 = 整项**转入；未开箱时单击 = 选手持；
  - 箱子行：**单击/滚轮 = 取 1 个**回背包、**双击 = 整项**取回；
  - 容量不够就转能装下的部分。

## 5. 拖拽（只剩树内移动）与滚动（纵向大纲，D-28）

- 树是**纵向大纲**（每节点一行、层级 = 缩进）：宽度有界，纵向随页面滚动；
- **树内移动**（重排表达式 = 编辑实参顺序/层级）：SortableJS `newIndex` 权威，
  走 `writeList`（先摘后插，节点永不重复引用，D-05）；大子树落到第 3 层及以下自动折叠；
- **边缘自动滚动**：真实拖拽由 SortableJS 的窗口自动滚动处理（默认配置）；
  放置模式由视觉层 rAF 循环驱动（指针停在视口上下边缘 60px 内滚页面，每帧重算落点）；
- **拖到侧栏 = 回收**（指针判定 `pointerOverSidebar`）；
- 背包/箱子不参与拖拽（物品表无槽位）；放置模式的落点不用拖拽（虚影 + 左键）。

## 6. 存档（`SAVE_VERSION = 4`）

```jsonc
{ "v": 4, "savedAt": 0, "roots": [...], "bag": { "iron_ore": "12", "iron": "3" } }
// 带内容的节点把物品表挂在节点条目上：{ type: "chest", collapsed: false, children: [], chest: { "coal": "7" } }
```

- 节点 id 不入档；`bag` 数量用字符串存（Decimal 纪律）；手持/放置模式是瞬态，不入档；
- **迁移链**（v1 → v2 → v3 → v4，`engine/save.ts`）：
  - v1/v2/v3 的节点背包**堆**与旧 `resources` 合并成 v4 `bag`：
    同名物品直接折算；节点类型按其**建造成本 × 数量**折算（保价值）；未知 id 丢弃；
  - 旧箱子的堆数组同样按成本折算成物品表。

## 7. 不变量（`store.spec` 有具名用例）

1. 同一节点在树中只出现一次（`writeList` 先摘后插）；
2. 建造是**原子**的：`payCost` 失败不动背包、不插节点；
3. 回收 = 成本分解成原材料 × 返还率（向下取整）+ 箱子内容原样（溢出才丢弃并提示）；
4. 转移前后「背包 + 箱子」总数不变（容量截断除外，且有提示）；
5. 结构变更后只重算「受影响节点 + 祖先链」的 `ret`（D-06）。
