# 11 · 踩坑实录(历史 bug 全录)

> 每条 = 现象 → 根因 → 修复(commit)→ 预防。按主题分组。
> 这些是用真实调试时间换来的结论;**改动相关区域前请重读对应条目**。

## §1 拖拽与 SortableJS

### 1.1 嵌套源拖拽"迟到的落账"
- **现象**:从嵌套(非根)列表拖出的节点,拖完状态不变;再点一下别处,变更突然出现。
- **根因**:合成输入过快时,Sortable 的落盘序列在 mouseup 之后才完成回写。
- **修复**(历史):落库整理统一延迟 `setTimeout(0)`(settle 系列)。
- **现状**:settle 体系已随跨区整树守卫退役(§1.9)——如今 @add 只做日志与
  展开 owner,不改拖拽物数据,本条经验留作"别在 @add 里同步改源数组"的提醒。

### 1.2 虚影方案两次返工
- 自制原生 setDragImage 小预览图:各端观感差、合成事件难测 → 弃;
- 回退原生 HTML5 DnD:合成测试完全无法驱动 → 弃;
- **终局**:`forceFallback:true` 全权交给库,CSS 只微调 `.sortable-fallback`。

### 1.3 面板底部空白投不进
- **根因**:根列表只包住内容,空白区域不属于任何 Sortable 列表。
- **修复**:`.tree-scroll` 纵向 flex + `.root-list{flex:1}` 撑满(b445e79)。

### 1.4 "挂为子节点"太难瞄准
- **修复**:拖拽中空子列表向上咬合父行下半部(`margin-top:-14px` 咬合区),
  悬停父行下半部即挂子;平时不占空间。

### 1.5 拖拽把库状态卡死
- **现象**:一次失败拖拽后,后续所有拖拽无效。
- **根因**:Sortable 的 dragEl 悬挂(没收到落手事件),后续 pointerdown 全被吞。
- **预防**:自动化里**每次拖拽测试刷新页面**;真人不受影响。

### 1.6 vue-draggable-plus 的内嵌 Sortable 用 mouseup 落手(不是 pointerup)
- 独立版 sortablejs 有 supportPointer→pointerup 分支,**内嵌版没有**。
- 合成事件以 `MouseEvent("mouseup")` 收尾才有效。浪费了整整一轮调试才定位。

### 1.7 后台标签页 rAF 冻结 → 拖拽半启动
- chosen 类已加、ghost 未建(_dragStarted 走 rAF)。页面必须前台。

### 1.8 真实输入(CDP)在 fallback 模式下不可靠
- 50ms `_emulateDragOver` 定时器 + 快速派发 = 插入判定从未运行。
- 结论:自动化一律用 09 §4 的合成协议;这**不代表真人有问题**。

### 1.9 守卫用 DOM 查子节点会漏判折叠节点;settle 体系随之退役
- 旧守卫② 用 `dragEl.querySelector(":scope > ol.child-list .node-wrap")`
  判断"带子节点的整堆"——但**折叠的非空节点不渲染子列表**(渲染条件
  `!node.collapsed || !hasChildren`),折叠堆拖进世界漏过守卫,
  靠 settleWorldDrop 事后拆堆兜底(展开堆则被拒——同一操作两种结果)。
- 修复:守卫改按**数据**判定(`findNode(dragId).children.length`),
  折叠与否不再影响;跨区整树(背包→世界 / 世界→背包)双向拒绝后,
  落库物必是单节点,settleWorldDrop/settleBackpackDrop 两条整理删除,
  "settle 必须 setTimeout(0)" 的整类问题不复存在。
- **教训**:守卫的判定依据应该是状态(数据),不是视图(DOM);视图是数据的
  有损投影(折叠/裁剪/条件渲染都会丢信息)。

### 1.10 验证 dev server 下发内容要带 base 前缀
- 本项目 vite `base:"/minode/"`,`curl localhost:1420/src/xxx` 拿到的是
  base 提示页(不是模块),grep 判"模块过期"会误判成 §6.1 的监听失效。
- 正确姿势:`curl localhost:1420/minode/src/xxx`。先用 base 前缀排除,
  再怀疑 watch 挂了。

## §2 堆叠与容量(三次绕过,一条条堵)

### 2.1 直接子节点数判定 → 嵌套子堆绕过
- 1 父 + 1 子堆(62 子):直接子数=1,远小于 63 → 任意塞(45613bb 修复:子树总量)。
### 2.2 owner 局部判定 → 挂满堆叶子绕过
- 把木头挂到满堆**内部叶子**的空子列表:owner=叶子,1+1≤64 恒过 → 堆悄悄膨胀(06a10f8)。
- 挂在 bench 下的堆同理(owner 链上是 bench,容量 ∞)。
### 2.3 第三版:同类链堆根判定(现已被展平不变量取代)
- `stackRootOf`(沿同类祖先上行,不越过功能节点)+ `canAbsorb`;
- 同时放行"同一堆内部整理"(dragRoot===pileRoot)避免误拦。
- **教训**:容量约束必须问"这次操作让**整堆**变成多少",而不是"直接父还装得下吗"。

### 2.4 手工合成被拖进世界
- 遗留的 `zones:["world","backpack"]` 没随设计收紧(cfe7a3a/3ee788b)。
- **教训**:设计变更(节点归属)时,registry zones、存档校验、上手指南三处同步。

### 2.5 现行:堆恒为「根+直接子叶」(用户裁决,取代递归判定)
- 拖堆入堆**自动展平**、超上限**填满溢出**(normalizePile 落库整理,
  必须延迟到 Sortable 回写后);背包不再出现"树嵌套树",存储永远是平的。
- 递归容量判定(stackRootOf/canAbsorb)随之退役——不是绕过被堵住,
  而是嵌套这个类别不复存在。堆父节点用"容器"视觉样式(整堆不可拖进世界)。

## §3 合成与消耗

### 3.1 混合子树虚计材料 + 连带销毁
- "bench→木棍(其下挂森林)":子树计数把森林算成木棍;移除木棍父节点时
  splice 连带删掉森林,无日志(440ab35 修复)。
- **修复**:计料与消耗都改为"每个同类节点计 1";takeNodes 叶优先,
  移除父时异类剩余子放回上层原位置。
- **教训**:计料口径与消耗口径必须**逐节点同源**,否则"数字够了、东西删错"。

### 3.2 多合成台/多探索节点错乱
- craftBench/explore 实现里读全局单例(benchNode/explorerNode),
  点击 B 台消耗 A 台材料(00f308e 修复:按发起节点结算;现行实现 =
  工作挂在发起节点上,resolveWork 对着同一节点结算)。

## §4 界面与交互

### 4.1 "IDE 工作台"风格被推翻
- 暗色三栏 + 底部导航 + 物品栏 → 全部重做为 orgro 式极简(浅绿白、无边框行、
  背包节点化、图鉴浮窗)。**教训**:界面隐喻与游戏气质匹配比信息密度重要。

### 4.2 折叠堆被获得物品自动展开
- 玩家明确反感。addItem/stackIntoBackpack 移除全部展开逻辑(b445e79);
  折叠时徽标 ×N 就是反馈。

### 4.3 空节点的残留对齐线
- 空(且折叠)的功能节点下面仍渲染一小段缩进引导线 → `border-left-color:transparent`(d539e62 一并处理省略号折叠)。

### 4.4 省略号在折叠时仍渲染
- `v-if="hiddenCount>0"` 漏了 `&& !node.collapsed`(d539e62)。
- **测试教训**:当时"验证失败"其实是同步读 DOM(渲染未 flush)——见 09 §3.1。

### 4.5 边缘滑动手势与节点拖拽冲突
- 贴边按住拖节点会同时开抽屉。修复:起点落在 `[data-node-id]` 不算边缘手势。

### 4.6 触发反馈的视觉三轮迭代(别走回头路)
- ①fireFx 图标弹跳 + 背景闪(用户:"潦草,不好看")→
  ②水平色波/灰波表达成功/无效("太花里胡哨,重要的是协调")→
  ③**工作进度条**(与工作时长系统配套,反馈服务于信息:这件事要做多久)。
- **教训**:装饰性反馈越做越抢戏;让反馈携带**玩法信息**(进度/忙碌)
  才既安静又有用。旧的 fx 事件总线(game/fx.ts)已随 ② 删除,别再引入。

### 4.7 截图断言前先确认标签页跑的是新代码
- vite HMR 在**后台标签页会推迟整页重载**,旧标签页残留旧 UI
  (实测:截到已删除的倒计时副标题,误判新代码没生效)。
- 处置:视觉断言前开**新标签页**或 reload;多个 localhost 标签先全关再开一个。

## §5 数据模型演进

### 5.1 count 字段时代(已废弃)
- v1-v4:`ItemStack{type,count}` / `GameNode.count?`。堆数量与树结构两套真相,
  不一致时徽标/容量/消耗互相矛盾。v5 起彻底删除,数量=子树大小。
- **教训**:派生数据不要落盘;单一事实源。

### 5.2 物品栏/底部导航(已删除)
- Minecraft 式 10 格热栏 + 底部导航曾是独立子系统(storageGroup/onHotbarOverflow/
  BottomNav),背包节点化后整体移除。历史代码不要再引入——背包分屏就是物品栏。

### 5.3 存档校验不是全函数
- `collect(backpack)` 在数组校验前执行,backpack=非数组时 TypeError
  (被上层 catch 吞掉报"读取文件失败",误导排查)。
- **教训**:布尔谓词对任意输入都不能抛;数组检查前置。

### 5.4 uid 撞号
- 手改档 uid=2 而存档里有 n5 → newNodeId 发出 n5,findNode/removeNode/Vue key 全乱。
- 修复:校验 uid ≥ 所有 `n<数字>` id 最大后缀。

## §6 工程环境

### 6.1 vite 文件监听静默失效(复发两次以上)
- 症状/鉴别/处置见 09 §3.2。改代码后"页面没反应"先查下发内容再查代码。

### 6.2 并行修改同一文件
- 本项目经历过"另一个会话/用户同时改代码"(types.ts 被外部重写、
  我的 python 补丁锚点失配静默失败)。**教训**:
  - 批量替换脚本必须 `assert old in s`,失败立即暴露;
  - 提交前 `git diff` 复核;
  - 发现陌生改动(如 .zcodeignore)先弄清来源再继续。

### 6.3 registry 非响应式 = 注册 API 是假的
- 普通集合上 push,图鉴 computed 无依赖永不重算——"时灵时不灵"的最坏假象(00f308e)。
- **教训**:跨模块可变数据 + computed 消费 = 必须响应式容器。

### 6.4 每秒全量写盘
- 游戏时钟放 store 里 → 每次 tick 持久化插件全量序列化(整树+200 条日志)。
- 修复:gameNow 模块级 ref(00f308e 之前的架构轮)。

### 6.5 内容注册必须先于存档校验与水合(架构轮:内容抽离 registry 后出现)
- 内容缺席时的真实后果(实测):`zonesOf` 对未注册类型 **fail-open**(返回
  全区域),isSaveValid 的 zoneOk 全放行——**存档不会被误清**;但水合后
  节点全部兜底成"未知的节点"、配方消失,玩家看到的是一个坏掉的世界。
- 规矩:main.ts **先 `import "./content"`(静态 import,模块体先于 main 体
  执行)再跑 ensureSaveIntegrity**;任何新入口文件同理。若日后把 zonesOf
  收紧为严格判定,这个顺序就会直接决定存档生死。
- **教训**:校验/渲染依赖注册表时,注册完成的时序就是正确性的一部分;
  fail-open 兜底掩盖不了内容缺席。

## §7 需求澄清记录(避免反复)

- "放置"一次只放一个;储区之间整堆(b445e79)。
- 触发前置检查:注定没有效果的触发(缺料/空挂/空手纯风味)**立即**拒绝或
  回应,不走工作时长——"材料不足也要硬控几秒"被用户明确反对。
- 流程参与物占用:祖先工作期间,其子节点置灰且点击被拦("正被占用"),
  让玩家看得出"森林正被石斧处理";拖走不拦(结算自然作废)。
- 交互范式(用户明确要求,两轮定稿):**行点击 = 折叠/展开**(与拖拽同为
  "组织树"的连续手势),**触发 = 行最左侧的触发按钮**——节点身份(图标+名字)
  合一成按钮;不要折叠箭头(行点击已承担),也不要把触发塞回行点击里。
  第一版"行尾圆钮 ⚡"被否:触发键应在左侧、且按钮要携带身份信息。
- click 链式传导(用户设计,取代"父节点开工"旧模型):**所有节点都会自动
  传导**;工具=自己没活干的瞬时传导者;**耗时发生在接收者身上**(森林被石斧
  砍伐,进度条在森林);断链(接收不了/忙碌/挥空)灰闪;探索/合成只收空手
  click 且不再传播;水车的计时要**可见**(cycle 进度条)。
- 堆叠展平:见 §2.5;堆父节点容器样式警示"整堆不可拖入世界"。
- 背包堆显示前 4 个子 + 省略号;徽标 = 挂载数 + 自己(25f5a26)。
- 手工合成天然在背包,方便批量挂料(4867ef6 架构轮)。
- 背包 = 世界的复刻:同构树、可嵌套、可与物品栏互通(现为与背包节点/世界互通)。
- 虚影交给 SortableJS 官方 fallback,不自造轮子(用户明确要求)。
